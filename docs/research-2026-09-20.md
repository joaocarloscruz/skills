## Demonstrated fixes

The catalog auditor used Markdown links to discover references but raw substring
matching to decide whether resources were used. Many canonical entrypoints use
standalone inline paths. Four regression tests failed on the baseline and pass
after the correction:

- A missing inline resource path escaped validation, including paths that left
  the package. Both now receive the same checks as Markdown links.
- An inline reference to a guide did not make the guide's own resources reachable.
  Traversal now follows these references and terminates on cycles.
- A filename mentioned only as a prefix of another filename incorrectly counted
  as used; an encoded Markdown destination could be incorrectly flagged unused.
  Reference matching now compares resolved targets.
- Markdown syntax shown inside an inline code example was treated as a live
  link. Code examples now remain examples; actual resources need explicit links
  or standalone inline paths.

An additional generator regression verifies that inline references back to an
entrypoint survive its rename from `SKILL.md` to `workflow.md` in router bundles.
The generator now rewrites these alongside ordinary Markdown backlinks.

The first remote Windows run then exposed mixed short/long temporary-directory
paths in the cycle test. A relative-path regression reproduced the underlying
duplicate document visit locally. Traversal now keys documents by resolved path,
so aliases and backlinks share one identity; fixture expectations use the same
canonical filesystem identity.

The parser deliberately supports the documented package subset, not arbitrary
Markdown or dynamically constructed paths. The bundled auditor remains
self-contained and uses only Python's standard library.

The conflict workflow now identifies merge, rebase, and cherry-pick operations,
checks the unmerged index, explains reversed rebase side names and missing index
stages, stages only intended paths, and continues the operation within the user's
scope. Its conditional reference cites Git's own manuals. Three added activation
fixtures cover rebase, markerless cherry-pick conflicts, and a conceptual Git
question that should not activate the workflow.

## Verification and limits

The four auditor regression cases were run red before the implementation change
and green afterward. The full validation command is
`uv run --with skills-ref==0.1.1 python scripts/check.py --official --require-powershell`.
Generated router packages are rebuilt from canonical sources and checked with
their ownership manifest.

Final local checks passed: 82 tests completed (73 passed, nine Windows symlink
privilege skips), all 52 packages passed `skills-ref` 0.1.1, both catalog audits
reported zero errors and warnings, and all 50 routing fixtures passed schema and
coverage checks. The two changed skills also passed the skill-creator validator.

Separately, commands in the Git reference were exercised in disposable
repositories with Git 2.55.0.windows.3: normal merge, a two-conflict rebase,
modify/delete cherry-pick without markers, and add/add with no base stage.
The merge and rebase checks preserved untracked notes. The smoke fixture initially
hit Windows CRLF whitespace; writing fixture data with LF resolved the harness
problem. These checks validate Git mechanics, not autonomous-agent effectiveness.

No paired model trials were conducted. Routing fixtures remain declared
expectations, and behavioral evidence remains `unvalidated`. No upstream skill
text or code was copied into the catalog. See [sources](../SOURCES.md) and the
[evidence registry](../evidence/skills.json) for provenance and revision pins.
